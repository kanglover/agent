# OpenAI《构建 AI Agent 实践指南》核心笔记

> 沉淀时间：2026-06-24
> 来源：https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/

---

## 一句话总结

从单 Agent 开始，用好工具和清晰指令，加上多层护栏保障安全；只有当复杂度真的撑不住时，才引入多 Agent 架构。先小后大，逐步验证。

---

## 核心是什么？

Agent = **能代替你独立完成任务的系统**。

它和普通聊天机器人的本质区别在于：Agent **自己控制任务的执行流程**，能判断、能行动、能纠错。

### Agent 的三个核心组件

| 组件 | 是什么 | 生活类比 |
|------|--------|----------|
| **Model（模型）** | 负责推理和决策的大脑 | 员工的脑子 |
| **Tools（工具）** | 能调用的外部能力（搜索/数据库/发邮件…） | 员工手里的工具箱 |
| **Instructions（指令）** | 告诉 Agent 怎么做事的规则 | 员工操作手册 |

---

## 解决什么问题？

帮助开发者判断：**什么场景该用 Agent，以及怎么设计它**。

---

## 什么时候该用 Agent？

三类最适合的场景：

| 场景 | 说明 | 举例 |
|------|------|------|
| **复杂决策** | 需要判断情境、处理例外，规则列不完 | 退款审批 |
| **规则太脆** | 大量 if-else，难维护、容易出错 | 供应商安全审查 |
| **非结构化数据** | 要处理自然语言、PDF、对话等 | 保险理赔处理 |

> ⚠️ 如果普通程序能搞定，就别上 Agent。

---

## 工具的三种类型

| 类型 | 作用 | 举例 |
|------|------|------|
| **Data（数据）** | 获取信息 / 查数据 | 查数据库、读 PDF、搜索网页 |
| **Action（操作）** | 执行动作 / 改变状态 | 发邮件、更新 CRM、转接客服 |
| **Orchestration（编排）** | 把另一个 Agent 当工具用 | 退款 Agent、研究 Agent |

---

## 怎么用？两种架构模式

### 1. 单 Agent 系统（推荐先从这里开始）

> 一个 Agent + 一堆工具，在循环中执行，直到任务完成

- 简单、好调试、好维护
- 大多数情况下够用
- 可用「提示词模板」管理不同场景，避免写太多重复逻辑

**何时考虑升级到多 Agent？**
- 指令里条件分支（if-then-else）太多，难以维护
- 工具之间职责重叠，Agent 频繁选错工具

---

### 2. 多 Agent 系统（复杂时才用）

两种模式：

| 模式 | 说明 | 类比 |
|------|------|------|
| **Manager 模式** | 一个主 Agent 统一调度多个专家 Agent | 项目经理 + 专业团队 |
| **去中心化模式** | Agent 之间互相移交控制权（Handoff） | 客服分机转接 |

**选择原则：**
- 需要统一控制 → Manager 模式
- 各自专注、互相转交 → 去中心化模式

---

## 指令（Instructions）写法建议

1. **用现有文档**：把客服手册、操作流程直接转成 Agent 指令
2. **拆细步骤**：把大任务拆成明确的小步骤，减少歧义
3. **定义清楚动作**：每一步要做什么、说什么，越具体越好
4. **覆盖边界情况**：用户信息不完整、问了意外问题，怎么处理

> 💡 可以用 o1/o3-mini 这类推理模型，自动把文档转成 Agent 指令格式

---

## 选模型的原则

1. 先用最强的模型建立性能基准
2. 再逐步换成更小的模型，看哪里不够用
3. 不同任务用不同强度的模型（分类任务用小模型，复杂决策用大模型）

---

## 护栏（Guardrails）——让 Agent 不出轨

护栏是多层防线，不能只靠一道：

| 护栏类型 | 作用 |
|----------|------|
| **相关性过滤** | 屏蔽偏题问题（"帝国大厦多高？" → 不回答） |
| **安全分类器** | 检测越狱 / 提示注入攻击 |
| **PII 过滤** | 防止泄露个人隐私信息 |
| **内容审核** | 过滤仇恨言论、骚扰等有害内容 |
| **工具风险分级** | 给每个工具打低 / 中 / 高风险标签，高风险需人工确认 |
| **输出校验** | 确保回复符合品牌价值观 |

**建护栏的顺序：**
1. 先关注数据隐私和内容安全
2. 根据真实遇到的边界情况，持续补充
3. 在安全性和用户体验之间找平衡，随 Agent 演进调整

---

## 人工介入：两种情况必须叫人

| 触发条件 | 说明 |
|----------|------|
| **失败超出阈值** | Agent 多次尝试仍无法完成，转人工 |
| **高风险不可逆操作** | 取消订单、大额退款等，先暂停确认 |

---

## 不适合用 Agent 的场景

- 任务简单、步骤固定 → 普通程序或 Workflow 就够
- 对稳定性要求极高 → Agent 推理有不确定性
- 没有合适的工具支撑 → Agent 无法行动
