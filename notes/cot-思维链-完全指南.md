# CoT（思维链）完全指南

## 一、CoT 是什么

CoT 是 "Chain of Thought" 的缩写，中文叫「思维链」。它是一种让 AI 在给出最终答案之前，先把思考过程一步一步写出来的技术。

### 生活中的例子

想象你问一个数学老师："小明有 3 个苹果，小红给了他 5 个，他又给了小刚 2 个，现在小明有几个苹果？"

**没有 CoT 的 AI** 会直接回答："6 个。" 你只知道答案，但不知道它怎么算的。

**有 CoT 的 AI** 会这样回答：

> 让我一步一步想：
> - 一开始小明有 3 个苹果
> - 小红给了他 5 个，所以 3 + 5 = 8 个
> - 他又给了小刚 2 个，所以 8 - 2 = 6 个
> - 答案是 6 个

思考过程暴露出来了，你可以检查每一步对不对。

---

## 二、为什么需要 CoT

AI 本质上是在做"文字接龙"——根据前面的内容，预测下一个最可能出现的词。如果没有 CoT，AI 可能会：

- **跳过关键步骤**，直接"猜"一个答案
- **在复杂问题上犯错**，因为中间某一步错了，后面全错
- **答案不可靠**，你不知道它是不是瞎蒙的

CoT 就像让 AI "慢下来，把草稿纸上的过程写出来"，而不是直接心算报答案。

---

## 三、CoT 有什么用

**1. 提升复杂任务的准确率**

数学题、逻辑推理、多步骤任务，CoT 能显著提高正确率。比如：

> "一个农场有鸡和兔，头共 35 个，脚共 94 只，鸡兔各几只？"

没有 CoT，AI 可能算错。有 CoT，它会一步步列方程、求解，不容易出错。

**2. 让答案可解释、可检查**

你能看到 AI 的"脑回路"，如果某一步错了，你可以指出并纠正。

**3. 帮助 AI 自己纠错**

把思考过程写出来，AI 能更容易发现"等等，这一步好像不对"，然后自我修正。

## 四、实际怎么用 CoT 写提示词

### 方法一：直接加一句魔法咒语

最简单的方法，就是在问题后面加一句：

> "请一步一步思考"（英文是 "Let's think step by step"）

这是经过大量验证的有效技巧。

**例子：**

```
用户：一个水池有进水管和出水管，进水管单独注满需要 6 小时，
出水管单独放空需要 4 小时，同时打开两个管子，多久能注满？

AI，请一步一步思考。
```

**AI 的回答会变成：**

> 让我一步一步分析：
> - 进水管的效率：1/6（每小时注入水池的 1/6）
> - 出水管的效率：1/4（每小时放掉水池的 1/4）
> - 同时打开，净效率：1/6 - 1/4 = 2/12 - 3/12 = -1/12
> - 等等，结果是负数，说明水在减少，永远注不满
> - 答案：无法注满，水会越来越少

AI 把每一步的逻辑都写出来了，你很容易发现它在哪一步可能出错。

---

### 方法二：给 AI 一个"思考模板"

对于更复杂的任务，你可以让 AI 按固定格式思考。

**例子：做决策分析**

```
请分析"我是否应该辞职去创业"，按以下步骤思考：

【步骤 1：列出已知信息】
- 我目前的工作状况是什么？
- 我的创业想法是什么？
- 我有哪些资源（资金、人脉、技能）？

【步骤 2：分析利弊】
- 继续工作的优点和缺点
- 创业的优点和缺点

【步骤 3：评估风险】
- 最坏的情况是什么？我能承受吗？
- 成功的概率有多大？

【步骤 4：给出建议】
- 基于以上分析，我的建议是什么？
- 如果决定创业，第一步应该做什么？
```

这样 AI 不会漏掉某个角度，输出也更结构化。

---

### 方法三：让 AI "先想后答"

你可以明确要求 AI 把"思考过程"和"最终答案"分开。

**例子：**

```
请回答以下问题。注意：先写你的思考过程，用 <思考> 标签包裹；
然后写最终答案，用 <答案> 标签包裹。

问题：某公司去年营收 1000 万，今年增长 20%，但成本也增加了 15%，
去年成本占营收的 60%，请问今年利润是多少？
```

**AI 会这样回答：**

```
<思考>
- 去年营收：1000 万
- 去年成本：1000 × 60% = 600 万
- 今年营收：1000 × 1.2 = 1200 万
- 今年成本：600 × 1.15 = 690 万
- 今年利润：1200 - 690 = 510 万
</思考>

<答案>
今年利润是 510 万。
</答案>
```

这样你可以单独检查 <思考> 部分，确认没问题后再看答案。

---

### 方法四：Few-shot CoT（给例子）

对于特别复杂的任务，你可以先给 AI 一个"示范"，告诉它你希望它怎么思考。

**例子：**

```
下面是一个推理问题的示例，请注意它的思考方式：

问题：小明比小红高，小红比小刚高，谁最高？
思考：小明 > 小红，小红 > 小刚，所以小明 > 小刚，小明最高。
答案：小明

现在请用同样的方式回答：

问题：A 比 B 大 3 岁，B 比 C 小 5 岁，A 和 C 谁大？大几岁？
思考：
```

AI 会模仿你给的示例格式，一步一步推理。

---

### 方法五：自我纠错 CoT

让 AI 在思考过程中"自我检查"。

**例子：**

```
请计算：15 × 28 = ?

要求：
1. 先给出你的第一次计算过程和答案
2. 然后检查一遍，看看有没有算错
3. 最后给出确认后的最终答案
```

**AI 可能这样回答：**

> 第一次计算：
> 15 × 28 = 15 × 20 + 15 × 8 = 300 + 120 = 420
>
> 检查：
> 让我用另一种方法验证：28 × 15 = 28 × 10 + 28 × 5 = 280 + 140 = 420
> 两次结果一致，应该是对的。
>
> 最终答案：420

---

## 五、写 CoT 提示词的要点总结

| 技巧 | 什么时候用 | 示例 |
|------|-----------|------|
| "请一步一步思考" | 通用，最简单 | 数学题、逻辑题 |
| 给思考模板 | 复杂分析任务 | 决策分析、方案对比 |
| 先想后答（标签分隔） | 需要检查过程 | 计算、推理 |
| Few-shot（给例子） | AI 不理解格式 | 特定格式的推理 |
| 自我纠错 | 容易出错的任务 | 复杂计算、长链条推理 |

## 六、Agent 代码中如何运用 CoT

### 6.1 核心概念：ReAct 模式

Agent 开发中，CoT 的工程化实现叫做 **ReAct 模式**（Reasoning + Acting）。

**ReAct = 推理（Reasoning）+ 行动（Acting）+ 观察（Observing）**

想象你是一位餐厅的主厨（Agent），你有一堆厨具和食材（各种工具）。当你接到一份订单（用户的任务）时，你不能把所有东西一股脑全用上，而是需要：

1. 先看订单是什么菜（思考）
2. 决定需要什么工具（刀、锅、烤箱等）（决策）
3. 按什么顺序使用（先切菜、再炒、最后装盘）（行动）
4. 每一步做完后，看看效果，再决定下一步（观察）

这个「思考→选工具→执行→观察→再思考」的循环过程，就是 Agent 中 CoT 的核心。

---

### 6.2 代码中的 CoT 循环

以 `calculator_agent.py` 为例，用户问："帮我算：25 加 37，然后把结果乘以 2"

**第 1 轮：AI 的"思考过程"**

```
👤 用户：帮我算：25 加 37，然后把结果乘以 2

🔧 AI 使用工具：add
   参数：{'a': 25, 'b': 37}
   结果：62
```

AI 没有直接回答"124"，而是先调用 `add` 工具。这个决策就是 CoT 的第一步：**先算加法**。

**第 2 轮：AI 继续"思考"**

```
🔧 AI 使用工具：multiply
   参数：{'a': 62, 'b': 2}
   结果：124
```

拿到 62 后，AI 继续推理：**接下来要乘以 2**，于是调用 `multiply`。

**第 3 轮：给出最终答案**

```
✅ 最终回答：25 加 37 等于 62，再乘以 2 等于 124。
```

---

### 6.3 关键代码：CoT 是怎么"驱动"的

看 `agent.py` 的核心循环：

```python
while step < MAX_STEPS:
    # THINK：调用 AI，让它决定下一步
    response = client.messages.create(
        model="claude-opus-4-8",
        system="你是一个助手，使用提供的工具完成任务。",
        tools=TOOL_DEFINITIONS,  # 告诉 AI 有哪些工具可用
        messages=messages,       # 把历史对话（含之前的结果）喂回去
    )
```

**CoT 的秘密就在这里：**

1. **`messages` 不断累积** —— 每轮 AI 的推理结果、工具执行结果都塞回去
2. **AI 基于完整历史做下一步决策** —— 这就是"链式思维"
3. **`system` 提示词引导思考方式** —— 告诉 AI 要先用搜索、再写摘要

### 6.4 复杂例子：ReActAgent 类

`03_react_agent.py` 实现了一个完整的 ReAct Agent，它把 CoT 的"思考链"工程化了。

#### 6.4.1 CoT 的可视化：trace 记录系统

```python
def _record_trace(self, step: int, event_type: str, content: str):
    entry = {
        "step": step,
        "type": event_type,      # "thought" / "action" / "observation" / "final"
        "content": content
    }
    self.trace.append(entry)
```

**这就是 CoT 的"黑匣子"**——把每一步的思考、行动、观察都记录下来。

运行时的输出长这样：

```
[1] 💭 THOUGHT
    让我分析一下用户的任务：需要搜索 Python asyncio 的信息，
    然后计算 2^10，最后给出总结。

[1] ⚡ ACTION
    调用 search_web({"query": "Python asyncio"})

[1] 👁️ OBSERVATION
    搜索 'Python asyncio' 的结果：Python asyncio 是标准库中的异步 I/O 框架...
```

Thought → Action → Observation 的链条清清楚楚。

---

#### 6.4.2 CoT 的驱动力：system 提示词

```python
system_prompt = (
    "你是一个 ReAct Agent，通过'思考→行动→观察'循环来完成复杂任务。\n"
    "每次回复前，先用简短的思考分析当前情况和下一步计划。\n"
    "灵活使用提供的工具来收集信息、计算、读写文件。\n"
    "当任务完成时，给出清晰的最终总结。\n"
    "始终用中文思考和回复。"
)
```

**这段提示词就是 CoT 的"开关"**——它明确告诉 AI：
- 你要先思考
- 思考完再行动
- 看到结果后继续思考

没有这个提示词，AI 可能直接瞎猜答案，不会一步步来。

---

#### 6.4.3 CoT 的循环引擎

```python
while step < self.MAX_STEPS:
    step += 1
    
    # 1. 调用 AI，让它思考下一步
    response = self.client.messages.create(
        model=self.model,
        system=system_prompt,
        tools=REACT_TOOLS,
        messages=self.messages
    )
    
    # 2. 解析 AI 的回复
    for block in response.content:
        if block.type == "text":
            # 提取思考文字
            self._record_trace(step, "thought", block.text)
        
        elif block.type == "tool_use":
            # 执行工具
            result = TOOL_MAP[tool_name](**tool_input)
            # 记录观察结果
            self._record_trace(step, "observation", str(result))
            
            # 关键：把结果塞回 messages，让 AI 下一轮继续思考
            self.messages.append({
                "role": "user",
                "content": [{"type": "tool_result", "content": str(result)}]
            })
```

**这个循环就是 CoT 的核心机制：**

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Thought   │────→│   Action    │────→│ Observation │
│  (AI 思考)   │     │ (调用工具)   │     │ (观察结果)  │
└─────────────┘     └─────────────┘     └──────┬──────┘
      ↑─────────────────────────────────────────┘
                    (结果塞回 messages，AI 继续思考)
```

### 6.5 实际运行示例

假设用户说："搜索 Python asyncio，然后计算 2 的 10 次方，给我总结"

**第 1 轮**

```
💭 THOUGHT: 用户需要两个信息：asyncio 的介绍，和 2^10 的值。
           我应该先搜索 asyncio，再做计算。

⚡ ACTION: 调用 search_web({"query": "Python asyncio"})

👁️ OBSERVATION: Python asyncio 是标准库中的异步 I/O 框架...
```

**第 2 轮**

AI 看到搜索结果后，继续思考：

```
💭 THOUGHT: 已经拿到了 asyncio 的信息。现在需要计算 2^10。

⚡ ACTION: 调用 calculate({"expr": "2 ** 10"})

👁️ OBSERVATION: 2 ** 10 = 1024
```

**第 3 轮**

AI 看到计算结果，认为任务完成：

```
💭 THOUGHT: 所有信息都收集完毕，可以给出最终总结了。

✅ FINAL: Python asyncio 是... 2 的 10 次方等于 1024。
```

### 6.6 简单 Agent vs ReAct Agent 对比

| | `calculator_agent.py` | `03_react_agent.py` |
|---|---|---|
| **CoT 体现** | 隐式的，AI 自己决定工具顺序 | 显式的，记录 Thought/Action/Observation |
| **调试能力** | 只能看到工具调用 | 能看到完整的思考链 |
| **任务复杂度** | 简单计算 | 搜索+计算+写文件，多工具组合 |
| **可追溯性** | 无 | 有 trace 记录，事后可复盘 |

### 6.7 更进阶：LangGraph 版本

`14_langgraph_react_agent.py` 用图（Graph）的方式实现了同样的 CoT 循环：

```python
# 节点 1：LLM 思考
graph.add_node("llm", llm_node)

# 节点 2：执行工具
graph.add_node("tools", tool_executor)

# 边：LLM → 工具 → LLM → 工具 → ... 循环
graph.add_edge("tools", "llm")  # 工具执行完，回到 LLM 继续思考

# 条件边：决定是继续循环还是结束
graph.add_conditional_edges("llm", should_continue, {
    "tools": "tools",    # 有工具调用 → 继续循环
    "__end__": END       # 无工具调用 → 结束
})
```

**用图的方式，CoT 循环变成了一张可视化的流程图**，更容易理解和扩展。

## 七、一句话总结

CoT 就是让 AI 展示思考过程，而不是只给答案。在 Agent 代码中，它体现为整个循环架构：

> **用户输入 → AI 思考 → 调用工具 → 观察结果 → AI 再思考 → 再调用工具 → ... → 最终答案**

每一轮都把历史塞进 `messages`，让 AI 基于完整的"思维链条"做下一步决策。
