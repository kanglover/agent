# RAG：检索增强生成

> 沉淀时间：2026-07-06

## 一句话总结

RAG = 让大模型"先查文档再回答"，解决幻觉和知识过时两大问题。

## 核心是什么？

大模型把知识"背"进参数，训练完就固定了，问到不知道的事就会胡说（幻觉）。

RAG 的思路：**回答问题前，先去知识库里检索最相关的内容，把原文一起传给模型。**

```
用户提问 → 向量检索 → 找到相关文档片段 → 注入 Prompt → 模型基于文档回答
```

## 解决什么问题？

| 问题 | 无 RAG | 有 RAG |
|------|--------|--------|
| 幻觉 | 模型凭记忆猜，答错也不知道 | 基于文档回答，可追溯来源 |
| 知识更新 | 重新训练模型（周级，极贵） | 更新向量库文档（秒级，极便宜） |
| 私有知识 | 无法使用（没训练进去） | 直接索引私有文档即可 |

关键 Prompt 约束（防幻觉的核心）：
```
仅根据以下【参考资料】回答问题。
如果资料中找不到答案，请回答"资料中没有相关信息"。
禁止编造资料中未提及的内容。
```

## 怎么用？三个阶段

### 阶段一：索引（提前做，只做一次）

```
文档 → 切块（Chunking）→ Embedding → 存入向量库
```

**分块策略（直接决定检索质量）：**
```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,    # 每块约500字
    chunk_overlap=50,  # 相邻块重叠50字，防止关键信息被切断
    separators=["\n\n", "\n", "。", "！", "？"]  # 优先按段落/句子切
)
```

### 阶段二：检索（每次提问时）

```python
def retrieve(question, vector_db, top_k=5):
    query_vector = embedding_model.encode(question)
    results = vector_db.similarity_search(query_vector, k=top_k)
    return results
```

### 阶段三：生成（注入 Prompt）

```python
system = """
仅根据以下【参考资料】回答：
{retrieved_chunks}
"""
answer = llm(system=system, user=question)
```

## Embedding 是什么

把文本变成数字向量，语义相近的词，向量距离也近：

```
"苹果手机" → [0.23, -0.51, 0.87, ...]
"iPhone"   → [0.21, -0.49, 0.85, ...]  ← 很接近！
"香蕉"     → [-0.62, 0.33, -0.41, ...]  ← 差很远
```

向量库（ChromaDB、Pinecone 等）就是利用这一特性做相似度搜索。

## 进阶：混合检索

| 方式 | 优点 | 缺点 |
|------|------|------|
| 向量检索 | 理解语义、同义词 | 精确关键词匹配差 |
| BM25（关键词） | 精确匹配强 | 不理解同义词 |
| **混合（推荐）** | 两者结合，效果提升10-20% | 实现稍复杂 |

Rerank 重排序：向量检索返回 Top-20 → 精排模型重新打分 → 取 Top-5 放进 Prompt。

## TF-IDF vs 语义 Embedding

- **TF-IDF**：按词频权重计算相似度，不理解语义，适合入门学习原理
- **语义 Embedding**：深度学习模型，理解同义词/上下文，生产必用
- "苹果" 和 "iPhone"：TF-IDF 认为完全不同，Embedding 认为高度相似

## 适用场景

- 企业私有知识库问答（内部文档、产品手册）
- 需要引用最新信息（新闻、政策、实时数据）
- 对准确性要求高、不能编造的场景（法律、医疗）
- 需要追溯来源的场景（"根据第X章..."）

## 不适合的场景

- 知识库很小且固定（直接全文放 context 更简单）
- 问题需要跨多个文档综合推理（RAG 只擅长单点查找）
- 对话闲聊类（不需要外部知识）
