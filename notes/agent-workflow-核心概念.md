# AI Agent 与 Workflow 核心概念

> 沉淀时间：2026-06-24
> 来源：https://www.anthropic.com/engineering/building-effective-agents

---

## 一句话总结

用最简单的方式解决问题，只在真正需要时才引入 Agent；能提前列出所有步骤的任务用 Workflow，步骤需要动态决策的任务才用 Agent。

---

## 核心是什么？

Anthropic 工程团队的实战结论：**成功的 AI 系统依赖简单、可组合的小模式，而不是复杂框架。**

### 两个关键概念

| 概念 | 定义 | 生活类比 |
|------|------|----------|
| **Workflow（工作流）** | 按预先设定好的步骤，让 AI 一步步完成任务 | 工厂流水线，每个工位做固定的事 |
| **Agent（智能体）** | AI 自己判断下一步怎么做，动态决策 | 有经验的员工，给他目标，他自己想办法完成 |

---

## 解决什么问题？

帮助开发者判断：**我的任务应该用 Workflow 还是 Agent？** 避免过度设计，也避免设计不足。

---

## 怎么用？

### 五种 Workflow 模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **顺序链（Prompt Chaining）** | 多个 AI 调用顺序执行，前一步输出是下一步输入 | 写草稿 → 翻译 → 润色 |
| **路由（Routing）** | 先分类用户意图，再转给专门的处理器 | 客服分流、多类型问题处理 |
| **并行处理（Parallelization）** | 同时执行多个子任务，或多个 AI 独立回答同一问题投票 | 加速处理、提高准确率 |
| **调度员-执行者（Orchestrator-Workers）** | 一个主 AI 分配任务，多个子 AI 执行 | 复杂任务拆分 |
| **生成-评估循环（Evaluator-Optimizer）** | 一个 AI 生成，另一个 AI 评价，反复改进 | 需要高质量输出的任务 |

## Workflow vs Agent 的边界

### 核心判断问题

> **在任务开始之前，你能把所有步骤都列出来吗？**

```
任务开始
   │
   ▼
步骤能提前确定吗？
   │
   ├─ 是 ──→ Workflow ✅（便宜、稳定、好调试）
   │
   └─ 否 ──→ 还需要问：
               │
               ├─ 只是有几个分支？ ──→ Workflow + Routing ✅
               │
               └─ 分支复杂、需要反复判断、
                  甚至要"回头重来"？ ──→ Agent ✅
```

### 对比表

| 维度 | Workflow | Agent |
|------|----------|-------|
| 步骤 | 固定，提前确定 | 动态，运行时决定 |
| 执行路径 | 每次基本一样 | 每次可能完全不同 |
| 工具使用 | 固定调用哪个工具 | 自己决定调不调、调哪个、调几次 |
| 成本 | 低 | 高 |
| 稳定性 | 高 | 较低（容易叠加错误） |
| 类比 | 按菜谱做饭 | 厨师根据食材即兴发挥 |

## 适用场景

### 用 Workflow 的场景
- 步骤固定、顺序确定的任务（如：翻译 → 润色 → 摘要）
- 需要稳定、低成本、易于调试的系统
- 任务有明确的分支但分支有限

### 用 Agent 的场景
- **开放性问题**：无法提前规划所有步骤（如：调研一个行业、写一份报告）
- **需要反复决策**：根据中间结果动态调整下一步
- **需要回头重来**：发现问题后可以重新尝试不同路径
- **工具使用不固定**：需要自己判断用什么工具、用几次

---

## 不适合用 Agent 的场景

- 任务简单、步骤明确 → 直接用单次 LLM 调用或 Workflow
- 对稳定性要求极高、不能出错 → Agent 容易叠加错误
- 预算有限 → Agent 成本更高

---

## 三个核心设计原则

1. **保持简单** — 不要为了用 Agent 而用 Agent，够用就好
2. **透明可观察** — 让 AI 展示推理过程，便于排查问题
3. **认真设计工具** — 给 AI 用的工具文档要写得清晰，像给人看一样

---

## 关于框架的建议

> 先从**直接调用 API** 开始，搞清楚底层原理，再考虑用框架（如 Claude Agent SDK）。框架能加速开发，但会增加不透明度。
